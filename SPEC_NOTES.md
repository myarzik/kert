# SPEC_NOTES

Deviations and resolutions against `kert_spec.md`. One line per entry.

- Task 0, §2.1/O2: spaCy pinned to `3.8.16` (newest 3.8.x with cp314 wheels for macOS/manylinux/win on PyPI) instead of `3.8.13` baseline; smoke check passed on 3.14.3 — Python 3.13 fallback NOT taken. Models: `ru_core_news_sm==3.8.0`, `en_core_web_sm==3.8.0`.
- Task 1, test_model::test_content_models_are_immutable, §3/D8: test defect (not a spec conflict) — assigned non-existent `id` on SplitCandidate/ChunkSpan; fixed in GREEN to assign the first declared field.
- Task 2, test_ingest_txt::test_utf8_bom_is_stripped, §4.1: a BOM is valid UTF-8, so the literal order `utf-8` → `utf-8-sig` would never reach `utf-8-sig` and leave U+FEFF in text; resolution: decode with `utf-8-sig` first (identical to `utf-8` for BOM-less input), then `cp1251` for `--lang ru`.
- Task 2, test_normalize::test_en_paragraph_starting_with_em_dash_is_dialogue, §4.3/D10: typing rule applied language-independently (§4.3 has no language condition); only dash normalization (§4.2) is RU-only.
- Task 4, test_candidates_rules (label-set tests), §4.5: en_core_web_sm uses ClearNLP labels, lacking obj/iobj/obl/acl:relcl/flat*/fixed. Resolution (user-approved): RU uses §4.5 labels verbatim; EN maps acl:relcl→relcl, obj→dobj, iobj→dative, obl→prep (cut before the whole PP, not before pobj), flat/flat:name/flat:foreign→compound, case→{prep, case}; `fixed` has no EN equivalent.
- Task 4, test_candidates_rules::test_*_no_cut_inside_chain*, §4.5 prohibition 1: "token i-1 or i is inside a chain" read per its stated intent (never split names/idioms): a chain is a connected component of flat/fixed (EN: compound) edges; a cut at i is suppressed iff min(chain) < i <= max(chain). Cuts before/after the chain stay allowed (user-approved).
- Task 4, test_candidates_rules::test_fallback_*, §4.5 fallback: for each mark 10, 20, … < n, emit 0.2 at the first index >= mark (and past the previous fallback cut) that passes all prohibitions; none if no such index < n (user-approved).
- Task 4, test_candidates_rules::test_left_fragment_never_a_lone_punctuation_token, §4.5 prohibition 5: since a cut never lands on punctuation (prohibition 4), a lone-punctuation left fragment can only arise at i == 1 with token 0 punctuation; implemented as exactly that check. "Inline" dialogue dashes (D10) exclude a sentence-initial dash.
- Task 5, test_pipeline::test_meta_values, §3 meta `title`: spec is silent on the title source for `.txt`; resolution: input filename stem (e.g. `book_ru.txt` → `book_ru`).
- Task 5, test_cli::test_force_*, §9 `--force`: compile writes into a temp file in the output directory and `os.replace`s it, so a failed compile never leaves a partial file nor destroys the existing output; stale `-wal`/`-shm` sidecars of the replaced file are removed (a foreign WAL next to a new DB risks corruption).
- Task 5, test_pipeline::test_output_is_a_single_file, §5/D8: test defect (not a spec conflict) — the module fixture held an open connection to the WAL database, which itself creates `-wal`/`-shm`; fixed in GREEN to snapshot the directory before connecting.
- Task order, §13.2: `kert inspect` (5a) needs the store (6) and chunker (7); order changed to 6 → 7 → 5a (user-approved) so inspect reuses them instead of duplicating DB reading and DP chunking.
- Task 7, test_chunker::test_overlong_chunk_avoided_when_bounded_partition_exists, §6/§10.3: the §6 cost alone does not guarantee "no chunk longer than 2W+2" (e.g. n=13, W=5, C={2:0.4}: one chunk costs 6.56 < 7.25). Resolution (user-approved): DP minimizes (number of chunks > 2W+2, §6 cost) lexicographically; the property is tested as "holds whenever the candidates admit such a partition".
- Task 7, test_chunker::test_tie_prefers_earlier_cut, §6: "ties broken by preferring the earlier cut" implemented as the lexicographically smallest cut sequence among equal-cost solutions (float ties within 1e-9).
- Task 7, test_chunker::test_property_no_chunk_starts_with_punctuation_on_compiled_book, §10.3: the first chunk of a sentence starts at the sentence start, not at a cut, and is exempt (a dialogue sentence begins with `—`).
- Task 7, test_chunker::test_length_penalty[17-8], §6: hand-arithmetic error in the golden — (9/8)^2 is 1.265625, not 1.140625; fixed the expected value to match the §6 formula.
- Task 8, test_config::test_config_path_is_xdg_on_linux_and_macos, §8.4: platformdirs' native macOS location (~/Library/Application Support) contradicts the spec's explicit `~/.config/kert/config.toml`. Resolution (user-approved): XDG rules (platformdirs Unix) on Linux and macOS, roaming %APPDATA% on Windows.
- Task 8, test_config::test_set_replaces_corrupt_toml_with_known_keys, §8.4: spec is silent on how `:set` writes TOML (stdlib has no writer). Resolution (user-approved): rewrite the file with only `chunk_width` and `theme` (other key keeps its current valid value); corrupt content and unknown keys are dropped; a write error is ignored (never crash on config errors).
- Task 8, test_config::test_invalid_*_falls_back_*, §8.4: "corrupt file → hardcoded defaults" applied per key — an invalid value (wrong type / out of range) in TOML or reader_state falls through to the next layer for that key only.
- Task 8a, test_state, §2/§13.1: the spec layout has no home for the pure `handle_key` state machine; it lives in `reader/state.py` (ReaderState, Book, effects). Side effects (advance_log rows, `:set` writes) are returned as `state.effects` for the task 9 glue to execute; `state.quit` signals quit.
- Task 8a, test_state::test_next_block_goes_to_its_first_chunk etc., §8.1/D5: "every forward/backward action appends one advance_log row" applied to chunk steps only (Space/j/→, b/k/←); J/K/gg/G/:goto skip text and do not log (user-approved). Boundary no-ops do not log.
- Task 8a, test_state::test_previous_block_goes_to_its_first_chunk, §8.1: K always goes to the first chunk of the previous block, even from mid-block (user-approved).
- Task 8a, test_render::test_neighbor_that_does_not_fit_is_dropped_whole, §7.1: a neighbor block is shown only if it fits whole (plus one blank separator) in the space above/below the vertically centered active block (user-approved). The text column is horizontally centered.
- Task 8a, test_state::test_percent_counts_only_words, §7.1: the Reader has no spaCy; a token counts as a word if it is alphabetic or numeric, approximating the compiler's `is_alpha or like_num` for `meta.word_count`. Percent is clamped to 100 (and 0 for word_count 0) to absorb any mismatch.
- Task 8a, test_state::test_goto_jumps_to_chunk_nearest_in_words, §8.2: "nearest chunk" = the chunk whose words-before count is closest to P% of word_count; ties go to the earlier chunk.
- Task 8a, test_state, §7.1/§8.2: the message area is cleared by the next key; command feedback for `:set` is `width=N` / `theme=X`; Backspace on an empty command line closes it, Esc cancels it.
- Task 9, test_roundtrip::test_full_session_roundtrip, §8.4: the `toml` fixture lived in the book's tmp dir, so the "only book.kert remains" check could never pass once `:set` creates the config dir; moved the fixture to its own tmp dir (assertion unchanged).
- Task 10, test_render::test_terminal_narrower_than_40_columns_shows_only_a_notice, §13.2: spec names "terminal < 40 cols" without behavior. Resolution: below 40 columns the frame is a single status-styled notice "Terminal too narrow: 40+ columns needed" (cropped to the width); keys keep working, so resizing re-renders on the next key and `q` still quits with save. No minimum height is enforced.
- Task 10, test_error_paths::test_book_without_text_is_user_error, §5: the compiler accepts an empty .txt (0 blocks); the Reader refuses such a book with a user error ("has no text to read") instead of opening an empty session.
- §7.1 change (user request, 2026-10-28): the layout is now "center focus" — the active chunk stays on the center row and text flows around it as a continuous tape (as many neighbor blocks as fit, cut at the screen edge, no `…` markers). Replaces "active block centered + one neighbor each side + tall-block clipping"; the §7.2 truncation-marker style is dropped. Supersedes the Task 8a neighbor note above.
- Task 13, test_render::active_rows helper, §14.7: the helper treated any bold text as the active chunk; headings are now bold even when inactive, so it matches the active-chunk colors (`white`/`black`) as well.
- Task 16 follow-up, test_normalize::test_lone_title_heading_does_not_swallow_chapters, §14.2: on a real Project Gutenberg EPUB (one h1 title, chapters as h2) "smallest present level" made the whole book one chapter. Resolution: the chapter level is the smallest level occurring at least twice, else the smallest present.
- Task 23, ReaderScreenTest::backSavesProgressAndReopeningResumes, §7.1: hand-arithmetic error in the golden — before "На улице было пусто." come 2 + 7 = 9 of 31 words (29.0%), not 6 (19.4%); fixed the expected value.
- Task 23, ReaderScreenTest::backSavesProgressAndReopeningResumes: test synchronization only — wait for the refreshed library row itself (`hasText("book_ru")`) before clicking it; the click raced the list re-composition. Asserted behavior unchanged.
- §4.4 change (2026-10-30): `exclude` instead of `disable` for NER and the lemmatizer, so pymorphy3 and its CC BY-SA dictionaries are never imported (smaller builds, no share-alike data in releases). Parses are unaffected: neither component feeds the parser.
